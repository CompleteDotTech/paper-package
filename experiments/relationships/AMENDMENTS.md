# Implementation and packaging clarifications

These clarifications were recorded after the first execution. They do not add arms, change regularization selection, alter the evaluated population, or select an operating point using evaluation labels.

1. Numeric implementation: fitted feature means/scales and coefficients are stored to eight decimal places; stacked probabilities are stored to eight decimals, with the largest coordinate adjusted to retain sum one. This makes the fitted transform, derived provenance, and graph replay portable across supported numerical runtimes. Optimizer diagnostics retain their declared tolerance. The finalized implementation was rerun after these changes.
2. Provenance binding was strengthened during review: derived decisions bind actual constituent probability vectors, both call identifiers, both request hashes, source model, and fitted transformation. A repeated request with a different response must not retain the same derived decision identity.
3. Packaging differs from the initial all-journals-in-Git plan. Git retains the complete numerical results reference, complete fitted transformation and training IDs, cross-validation summaries, generated tables, and hashes identifying the full local execution. Full per-example and out-of-fold journals are regenerated by the committed code and archived in every CI run, with 90-day requested retention. The exact decompressed evaluation decision journal hash is enforced by CI. Artifacts expire; permanent reproduction depends on the committed original observations and executable experiment, not artifact availability. The final handoff also includes the full local execution bundle.

The original protocol is preserved. These are numerical/provenance/storage clarifications, not a new experiment or an independent confirmation. No result was excluded because it was negative.
