# Five reliability and structural improvements: frozen exploratory protocol

Date: September 18, 2026. Baseline: `338981392c77f4771cdbb58a9f8c90fd723da64a` (merged PR #16). This protocol is committed before executing the extension. Published evaluation results have already informed the hypotheses: this is exploratory follow-up, NOT independent preregistration. Do not change primary criteria after inspecting outcomes. ## Motivation and evidence boundary

The adaptive and risk-control studies show correlated verification errors, expensive review-risk features, an optimistic source-group risk objective, and exact optimization benefits restricted by graph structure. Earlier lineage bounds prevent duplicate-evidence inflation but can be conservative. We test five specific engineering improvements, not the invention of new statistical or optimization mathematics. No production graph policy changes. Fresh Jev calls in this extension: zero. H1 uses authentic captured predictions; H2 simulates review of those predictions. H3-H5 use explicitly controlled algorithmic fixtures, not new scientific-document extraction, source truth, or a KARMA comparison.

All response replay uses the existing 73 development candidates / 40 source groups and 263 evaluation candidates / 149 source groups. These evaluation groups are already inspected, not a new holdout. Verify source hashes, original response reconstruction, unique IDs and group separation. Fitting may use development gold only; policy execution accepts gold-free features. Preserve invalid responses and all archived study files. Charge recorded feature-acquisition tokens, including failed calls. Do not equate counterfactual token totals with measured latency or reviewer cost.

## H1: Out-of-group calibration of source-contamination risk

Hypothesis: leaving one development source group out during calibration reduces optimism in the existing independent-edge group-risk model. Use the adaptive risk model (label, score >=0.90, compact disagreement) without changing its bins. For each of the 40 development groups, fit that model on the other groups and predict contamination for the held-out group's accepted base1 edges. Empty accepted groups are excluded from the primary calibration endpoint. For fixed multipliers k in {0.25,0.5,0.75,1,1.5,2,3,4}, transform q to 1-(1-q)^k. Choose minimum out-of-group Brier score, breaking ties by distance from 1 then smaller k. Refit the edge model on all development rows and apply the selected k to test group probabilities. Compare against k=1 on the SAME nonempty accepted groups. Report Brier, clipped log loss, observed and predicted contamination, calibration bias and all fold predictions. Primary: at least 10% lower test-group Brier AND absolute mean calibration bias <=0.03. This is a proper-score engineering target, not a guarantee that correlated group risk is calibrated in deployment. Report a paired group-bootstrap interval for the Brier difference.

## H2: Single-view, feature-parsimonious review prioritization

Hypothesis: removing compact-disagreement features preserves review effectiveness while eliminating unnecessary acquisition cost. Fit the same two-pseudo-observation shrinkage risk estimator on development accepted edges, using ONLY base1 label and the fixed score >=0.90 indicator. Compare to the existing three-feature adaptive risk model. Both use the same group-aware greedy order and fixed primary budget of 20 reviewed edges. Primary simulated reviewer detects every wrong reviewed edge, never removes correct edges and adds no missing edges. Primary: no more contaminated groups, no fewer correct retained edges, and at least 25% lower recorded feature-acquisition input tokens. Also report budgets 10,30,40 and sensitivity {0.5,0.75,1} x false-removal {0,0.01,0.05}. Real reviewer skill, cost and causal benefit remain unmeasured. Report selection IDs and an equal-budget paired group-bootstrap difference; feature costs must include all candidate decisions, not just reviewed positives.

## H3: Exact small-lineage evaluation with conservative fallback

Hypothesis: exact evaluation of bounded shared-lineage components recovers justified admissions lost by conservative bounds without reintroducing duplicate inflation. Proofs are nonempty conjunctions of explicitly independent primitive Bernoulli events with supplied probabilities. Canonicalize duplicate/subsumed proofs, split disjoint primitive-event components, and evaluate each component by memoized Shannon expansion with a fixed 16-atom cap and 32768-state budget. If either cap is exceeded, return the existing component max-proof / sum-proof bounds; never return a partial exact value as certified. Combine disjoint components by independence. Primary: zero disagreements beyond 1e-12 with independent exhaustive event enumeration on 128 seeded <=8-atom fixtures, invariance to proof order and 1/2/5/20 duplicate copies, zero false lower-bound admissions at 0.95, and at least one exact high-probability admission recovered from conservative lower-bound staging. Include analytic shared-atom fan cases, over-cap staging/bounds and incorrect-lineage negative controls. Report widths and recursion-state counts; scores are supplied primitive probabilities, NOT raw Jev confidence or inferred source independence.

## H4: Bounded cycle-cutset conflict optimization

Hypothesis: conditioning on a small cycle cutset extends exact maximum-priority conflict resolution beyond the previous forest-only capacity. Input is an explicitly supplied undirected conflict graph with unique string IDs and nonnegative integer priorities. Handle connected components independently; cap each at 256 vertices. Remove leaves to expose the cycle core and greedily remove its highest-degree vertex (ID tie break) until the remainder is acyclic, allowing at most four cut vertices. Enumerate independent choices of cutset vertices, exclude their neighbors, and solve the remaining forest by include/exclude dynamic programming. If the cutset cap fails, retain exhaustive optimization for components <=16 and stage larger unsupported components. Compare with the prior forest-plus-small-exhaustive policy, priority-first greedy and independent subset enumeration. Primary: zero oracle/consistency failures on 128 seeded <=10-vertex cases, no small-component utility regression, deterministic input-order invariance, and exact unstaged solutions on all ten cycle/wheel fixtures at sizes 17,32,64,128,256. Include a dense 17-clique staging control and a higher-priority-false semantic counterexample. Structural optimality is not semantic truth; supplied abstract conflict topologies are not extracted scientific graphs.

## H5: Dependency-local incremental conflict maintenance

Hypothesis: re-solving only components affected by a graph mutation preserves full recomputation outcomes while reducing solver work. Cache component solutions from H4. For weight changes, edge insertions/deletions and vertex insertions/deletions, invalidate old components touched by changed endpoints and new components reachable from those touched nodes. Reuse only byte-identical unaffected components. Full graph validation/change detection remains explicit; the work metric counts vertices submitted to the solver, NOT total CPU time or asymptotic end-to-end complexity. Primary: zero selected/staged/utility mismatches versus full H4 recomputation across 640 seeded mutations including bridge merges/splits and vertex deletion, and at least 75% fewer solver-vertex visits on a fixed 64-component, eight-vertex-per-component local-weight-update workload of 128 updates. Report a connected-graph stress control where savings can disappear, invalid-input rejection and deterministic replay. This is an in-memory opt-in prototype, not a durable transaction engine or production benchmark.
