## Motivation, evidence boundary and fixed inputs

The adaptive extension saved only 34.38% of tokens with disagreement routing, recovered operational failures at the expense of additional wrong edges, found no matched-volume benefit from redundancy-capped voting, and showed conditional gains from group review and bounded conflict optimization. We test five distinct refinements of those findings. H1-H3 replay authentic recorded responses. H4 uses observed source groups under a simulated reviewer and independent small optimization oracles. H5 uses controlled qualifier graphs and independent finite/analytic oracles. Fresh Jev service calls: zero. Recorded-token counterfactuals are not fresh latency, invoice or independent semantic-generalization measurements. No production/default graph policy changes.

Preserve the multicall source split: 73 development rows in 40 source groups, 263 test rows in 149 groups. Fit on development labels only; policy execution receives no gold. Never silently repair invalid probability vectors or treat correlated views as independent evidence. All physically required calls, including failures and preliminary calls, are charged once. Publish policy selections, every prediction, negative results and source hashes. The previously published test is not a new holdout.

## H1 — Compact-only expected-value routing

Hypothesis: a development-fit action table avoids paying for a second preliminary reviewer while preserving rich-prompt edge quality. Bins use only compact label and score >=0.90. Utility is correct accepted edge minus five times wrong accepted edge; nonedges earn zero. Estimate rich-minus-compact utility per bin, shrinking with two global-prior pseudo-observations. Escalate when estimated advantage exceeds a penalty times mean rich input tokens/1000. Penalties: {0,0.01,0.05,0.1,0.25,0.5,1}. Invalid compact calls always escalate. Select the cheapest development-feasible policy retaining >=98% of rich correct edges with no extra wrong edges; include direct-rich as a feasible fallback without compact overhead. Freeze the selected table before evaluating test. Compare rich, compact, prior confidence/disagreement routes and the new policy. Primary test conjunction: >=40% recorded-token saving versus rich, >=98% correct-edge retention and no extra wrong edges. Misses are retained; fitting uncertainty and previous test exposure prevent confirmatory inference.

## H2 — Source-group risk-certified recovery gate

Hypothesis: a simultaneous group-error upper-bound gate can constrain the previous dependency-safe fallback without vacuous loss of useful graph output. Apply five fixed positive-acceptance thresholds {0,0.90,0.95,0.99,1} to the saved dependency-safe fallback. For each development source group, loss is one iff any accepted edge is wrong; groups with no accepted edges have loss zero. Compute one-sided exact binomial upper bounds with Bonferroni alpha=0.05/5, treating the 40 groups as units. Select the nonempty candidate with most accepted development edges whose bound is <=0.15, breaking ties toward the lower threshold. If none qualifies, stage all and explicitly report no nontrivial certificate. This is a diagnostic application of risk-control mathematics, NOT a deployment guarantee: independence/exchangeability and an untouched selection/calibration protocol are not established by this reused research data. Primary test conjunction: a nonempty candidate qualifies, >=90% of single-rich correct edges retained, and observed any-error frequency across all 149 test groups <=0.15. Report conditional contamination among nonempty groups, edge precision, false/missed edges, stage-all fallback and calibration counts; do not confuse group risk with edge precision. Validate binomial inversion numerically, boundary cases and multiplicity adjustment. Learn-then-Test is context, not a newly proved guarantee for this dataset.

## H3 — Direct, support-only qualifier veto

Hypothesis: logical use of the six existing dimension checks can reject unsupported SUPPORTS edges more efficiently than adding an adjudicator. Obtain base1 first. For a SUPPORTS answer only, obtain the existing checks call; an invalid check vector stays an operational error, with no normalization or fabricated response. With valid checks, stage the candidate if any dimension assigns MISMATCH probability >=0.90. Keep other valid base labels unchanged: a mismatch can legitimately support REFUTES, so do not apply a SUPPORTS-specific conjunction to REFUTES. Never obtain the adjudicator. Compare single-rich, prior targeted, invalid-only gating and this veto. Primary conjunction: >=20% fewer wrong edges than confidence-ranked single-rich at the same accepted volume, >=95% correct-edge retention versus single-rich, and <=1.5 times its recorded tokens. k is the minimum positive accepted volume of single-rich and veto; fixed ID tie breaks. Publish removed correct edges and invalid-versus-valid veto attribution. This tests bounded verification of supplied candidate claims, not open-ended relationship extraction.

## H4 — Budget-optimal review under imperfect detection

Hypothesis: exact allocation across source groups improves on one-edge-at-a-time greedy review, which can miss complementary multi-edge cleanup. Reuse development-only shrinkage risks from the previous study. Fixed reviewer sensitivity=0.75; false-removal probability=0.05. For each group and k, its best k-item subset under the independent-risk model contains the k highest estimated risks. Expected contamination is one minus the product of (1-p) for unreviewed edges and (1-p+0.75p) for reviewed edges. Dynamic programming allocates exactly min(budget,n) reviews across group options. Compare against a sensitivity-aware greedy policy optimizing the same marginal objective and the prior ideal-review greedy ordering. Budgets {10,20,30,40}; primary budget 20. Primary empirical-simulation conjunction: strictly fewer expected contaminated observed source groups than sensitivity-aware greedy and no fewer expected retained correct edges. Separately require modeled objective never worse at any listed budget and zero optimum errors on 64 seeded eight-edge fixtures checked by independent subset enumeration at budget three. Include a two-high-risk-edges-in-one-group counterexample. False removal is evaluated but is not part of the allocation objective; include sensitivity {0.5,0.75,1} and false removal {0,0.01,0.05}. Estimated independence, review sensitivity and review cost are assumptions, not measured human performance. Charge single-plus-compact feature acquisition, before review cost.

## H5 — Forest-aware exact conflict optimization

Hypothesis: exploiting acyclic conflict components removes unnecessary staging beyond the prior 16-assertion cap without sacrificing supplied-weight optimality. Build the existing scope/interval conflict graph. For forest components, use include/exclude tree dynamic programming; for cyclic components of at most 16, retain exact enumeration; stage larger cyclic components. Bound every component at 256 assertions. This extension supports nonnegative integer priorities and stages unsupported inputs explicitly. Compare the prior bounded optimizer and priority-first greedy. Validate 64 seeded eight-assertion fixtures using the independent integer-time truth oracle, input-order invariance, all small unweighted graph shapes arising in the fixtures, and analytically solvable stars/paths at n={17,32,64,128,256}. Primary conjunction: zero consistency/optimality failures on all supported oracle fixtures; no utility regression against the prior optimizer on supported <=16 components; positive optimal utility without staging on every large star/path fixture. Record selected/staged/rejected sets, algorithm route and utility, not just timing. Test a 17-node odd cycle and an over-limit forest as staging controls; unsupported qualifier/priority inputs; a high-priority false-assertion semantic control. Exact consistency and supplied-weight utility do not establish truth. Graph construction remains quadratic; this is not an unbounded database-scale performance claim.
