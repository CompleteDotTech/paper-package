## H1: Estimate source contamination directly

Motivation: PR #17's product-risk multiplier improved bias but worsened Brier. Replace products of edge correctness with a directly fitted Bernoulli source event: whether any base1-accepted edge in that source is wrong. Use two predeclared binary features: at least two accepted edges, and any accepted base1 score below 0.90. For each feature cell use (cell errors + alpha * global source error rate)/(cell count + alpha), with global rate smoothed by Beta(1,1). Choose alpha from {1,4,16} using leave-one-development-source-out Brier, ties favoring stronger shrinkage. Compare with both PR #17's raw product and its development-selected multiplier model. Primary conjunction: at least 10% lower evaluation Brier than the better of those two comparators AND absolute calibration bias <=0.03 on identical nonempty accepted source groups. Report all folds, cell counts, probabilities, proper scores and paired intervals. No independence guarantee is implied.

## H2: Charge for opening source documents during review

Motivation: previous review analyses charged only edge reviews, not document setup. Use PR #17's single-view edge-risk fit. Compare its group-aware greedy order, admitted while respecting actual remaining setup-plus-edge budget, with an exact multiple-choice knapsack over source-specific risk-ranked prefixes. Each group offers no review or its top k risky edges. Expected source-decontamination benefit uses assumed independent edge errors and reviewer detections. Primary: budget 40 units, opening a source costs 2, each reviewed edge costs 1, detection 0.75, false removal 0.01. Target: at least 0.5 fewer label-evaluated expected contaminated groups, at most 0.1 additional expected correct edges removed, and no overspend. This is a hypothetical cost model, not measured human cost. Sensitivities: budgets {20,40,80}, setup {0,1,2,5}, detection {0.5,0.75,1}, false removal {0,0.01,0.05}; retain a within-source perfectly correlated detection control. Selection receives no evaluation gold. Independently enumerate small knapsack fixtures to check optimization. Charge recorded single-view feature tokens separately.

## H3: Replace atom-count limits with bounded frontier evaluation

Motivation: PR #17 stages shared-lineage components with >16 atoms even when overlap is narrow. Compute monotone-DNF probability by an iterative frontier dynamic program over sorted primitive IDs, tracking assignments only for processed atoms appearing in unfinished proofs, and discarding states once a proof succeeds. Caps: 256 atoms, 1,024 proofs, frontier width 12, 65,536 state transitions; when unsupported fall back to the prior exact/bounded lineage routine, never claim a partial evaluation as exact. Inputs are supplied independent Bernoulli primitives, not calibrated Jev truth probabilities. Primary: zero errors above 1e-12 on 192 seeded random cases (2-10 atoms); order/duplicate invariance; zero false lower-bound admissions; and exact analytic agreement for ten path/cycle fixtures at 17,32,64,128,256 atoms. At least one large connected fixture must tighten the prior interval. Retain empty/constant cases, p=0/1, cap failures, a dense 17-atom case, and falsely split shared-source independence control. No algorithmic novelty or service-latency claim.

## H4: Solve bipartite conflicts using a flow certificate

Motivation: a four-vertex cycle cutset does not cover many grids and dense bipartite conflicts. Detect bipartite connected components, reduce nonnegative integer-priority independent set to a minimum vertex cover/minimum cut, and return a checkable feasible-flow/cover certificate. Keep the existing 256-vertex cap; unsupported/nonbipartite components delegate to PR #17's solver. Bound residual-edge inspections at 2,000,000 per component; exhaustion delegates rather than promoting an unfinished solution. Primary: no objective/consistency regression against finite enumeration or the previous solver on 192 seeded small random graphs; deterministic order invariance; exact analytic objective and valid certificates on ten large cases (square grids of sides 5,6,8,12,16; complete bipartite graphs with 9,16,32,64,128 vertices per side); improve at least four large-case objectives over the prior policy. Include zero weights, disconnected graphs, invalid inputs, dense nonbipartite staging, deliberately damaged certificates, and a false high-priority assertion control. Factual correctness is separate from the supplied optimization objective.

## H5: Revision-checked source-lineage cache maintenance

Motivation: evidence retractions and changed probabilities require lineage-aware invalidation, not only conflict-component caching. Index primitive-to-fact dependencies, recompute only affected fact probabilities on source-value deltas, and maintain the index on fact proof replacement/addition/removal. Validate optimistic revision and all inputs and compute replacements before committing state; reject invalid/stale updates atomically. Revocation is an explicit probability-zero input. This is an in-memory prototype, not a durable or concurrent database. Primary: zero stale-probability or state mismatches on 640 seeded mutations plus explicit retraction, proof replacement, deletion/reinsertion, stale-revision and exception rollback controls; at least 90% fewer fact reevaluations including cold build on 128 independent three-atom/two-proof facts with 256 local updates. Report dependency-index touches separately; do not equate fact reevaluations with total CPU time. Retain a global-source control where all facts require invalidation and no evaluation savings are expected.

Primary sources consulted: TypeSafe introduction (https://docs.typesafe.ai/introduction); Amarilli et al., Connecting Knowledge Compilation Classes and Width Parameters, arXiv:1811.02944; NetworkX minimum_cut documentation (https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.flow.minimum_cut.html).
